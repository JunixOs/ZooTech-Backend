ZOO | API CONTRACT - Módulo Vacuno
Estructura solicitada: Endpoint, Método HTTP, Request, Response, Códigos de estado, Validaciones y Errores
Módulo:
Vacuno
Ruta base:
/v1/vacunos
Estándar:
OpenAPI 3.0 - contrato funcional por endpoint
Autenticación:
Bearer Token JWT en todos los endpoints
Versión:
1.0.0
Regla general: el contrato define lo que el frontend puede consumir y lo que backend debe implementar antes de empezar el código.
1. Listar vacunos
Endpoint:
/v1/vacunos
Método HTTP:
GET
Request:
Query params:
• page: integer opcional. Valor por defecto: 1.
• limit: integer opcional. Valor por defecto: 20.
• fechaDesde: date opcional. Por defecto: hoy - 30 días.
• fechaHasta: date opcional. Por defecto: hoy.
• q: string opcional. Busca por código o nombre.
• raza: string opcional. Filtra por raza.
• procedencia: string opcional. Filtra por granja, distrito, provincia o departamento.
• estado: enum opcional. Valores: vivo, muerto.
Ejemplo:
GET /v1/vacunos?page=1&limit=20&fechaDesde=2024-03-01&fechaHasta=2024-03-31&q=VACA001&estado=vivo

• Por defecto se muestran registros de los últimos 30 días.
• page y limit deben ser numéricos.
• fechaDesde y fechaHasta deben usar formato YYYY-MM-DD.
• estado solo permite vivo o muerto.
• La búsqueda general aplica sobre código o nombre.
• El listado debe devolver paginación estándar.

3. Registrar vacuno
Endpoint:
/v1/vacunos
Método HTTP:
POST
Request:
Body multipart/form-data:
• codigo: string requerido, máximo 10 caracteres, único y en mayúsculas.
• nombre: string requerido, máximo 15 caracteres.
• fechaNacimiento: date requerido.
• adquisicionPor: enum requerido. Valores: monta, compra. Default: monta.
• precioCompra: number condicional. Obligatorio si adquisicionPor = compra.
• raza: string requerido. Default sugerido: Angus.
• color: string requerido, máximo 15 caracteres.
• sexo: enum requerido. Valores: macho, hembra. Default: hembra.
• codigoPadre: string requerido, máximo 10 caracteres, en mayúsculas.
• codigoMadre: string requerido, máximo 10 caracteres, en mayúsculas.
• granja: string requerido, máximo 15 caracteres.
• distrito, departamento, provincia: string requeridos.
• aptoPara: enum requerido. Valores: produccion_leche, carne, reproduccion.
• fechaEspecificacion: date requerido.
• foto: archivo opcional PNG/JPG.
• observaciones: string opcional, máximo 150 caracteres o 30 palabras.
Response:
Campo
Tipo
Descripción
id
integer
ID generado.
codigo
string
Código registrado.
nombre
string
Nombre registrado.
fechaNacimiento
date
Fecha registrada.
adquisicionPor
enum
Forma de adquisición.
precioCompra
number/null
Precio registrado o null.
fotoUrl
string/null
URL de foto almacenada.
creadoEn
date-time
Fecha de creación del registro.
Códigos de estado:
201 Created
Vacuno registrado correctamente.
400 Bad Request
Datos inválidos.
401 Unauthorized
Token ausente o inválido.
409 Conflict
Ya existe un vacuno con ese código o datos repetidos.
500 Internal Server Error
Error no manejado del servidor.
Validaciones:
• No se permite registrar un vacuno si ya existe registro del mismo vacuno.
• Código máximo 10 caracteres y en mayúsculas.
• Nombre, color, granja y demás inputs de texto no deben exceder 15 caracteres cuando aplique.
• Observaciones máximo 150 caracteres o 30 palabras.
• Foto solo acepta PNG, JPG o JPEG.
• Campos numéricos no deben aceptar letras.
• precioCompra es obligatorio solo cuando adquisicionPor = compra.
• Todos los campos obligatorios deben estar presentes.
Errores:
VALIDATION_ERROR
400 - Campos inválidos o incompletos.
VACUNO_ALREADY_EXISTS
409 - Código o datos del vacuno repetidos.
UNAUTHORIZED
401 - Token ausente o inválido.
INTERNAL_SERVER_ERROR
500 - Error interno.

5. Eliminar registro vacuno
Endpoint:
/v1/vacunos/{vacunoId}
Método HTTP:
DELETE
Request:
Path params:
• vacunoId: integer requerido.
Body application/json:
{  "razon": "Registro duplicado con datos incorrectos"}
Response:
Campo
Tipo
Descripción
Sin contenido
204
La respuesta exitosa no devuelve body.
Códigos de estado:
204 No Content
Eliminación lógica realizada correctamente.
400 Bad Request
No se envió razón de eliminación.
401 Unauthorized
Token ausente o inválido.
404 Not Found
El vacuno no existe.
409 Conflict
El vacuno tiene dependencias activas.
500 Internal Server Error
Error no manejado del servidor.
Validaciones:
• La eliminación requiere confirmación del usuario.
• razon es obligatoria para auditoría.
• El registro desaparece del frontend, pero se conserva en base de datos por trazabilidad.
• Solo se elimina si no tiene registros dependientes activos: triajes, incidentes, ordeños, etc.
• Si hay dos registros iguales, se elimina el que no tenga dependientes; si ambos tienen, se elimina el último registrado.
Errores:
VACUNO_NOT_FOUND
404 - No existe el vacuno.
VACUNO_HAS_DEPENDENCIES
409 - Tiene triajes, incidentes u ordeños activos.
VALIDATION_ERROR
400 - Falta razón de eliminación.
UNAUTHORIZED
401 - Token inválido.

Formato estándar de error
Todos los endpoints deben devolver errores con el siguiente formato:
{  "error": {    "code": "VALIDATION_ERROR",    "message": "Los datos enviados no son válidos.",    "details": [      { "field": "codigo", "message": "El código no puede exceder 10 caracteres." }    ]  }}
Checklist de entrega
• Cada endpoint contiene: Endpoint, Método HTTP, Request, Response, Códigos de estado, Validaciones y Errores.
• Todos los endpoints requieren Bearer Token JWT.
• Los endpoints de listado y reportes aplican filtro por últimos 30 días por defecto.
• Las descargas de reportes y gráficos permiten PDF y Excel.
• Los errores usan code en UPPER_SNAKE_CASE, message y details.
• Las validaciones del documento de requisitos están reflejadas en los endpoints.
